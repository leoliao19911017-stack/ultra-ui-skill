# Ultra UI Skill

## Core principle

Great UI is opinionated, coherent, and useful. Explore broadly before committing, then subtract aggressively before delivery.

## Workflow

1. Frame the product, audience, primary task, content, platform, and constraints.
2. Explore genuinely different directions; do not reskin one familiar layout.
3. Convert the chosen direction into observable design decisions and explicit avoidances.
4. Build, capture, and critique the result from an isolated visual context.
5. Add generated media only when it strengthens meaning or interaction.
6. Remove anything that does not improve comprehension, action, feedback, or identity.
7. Verify real content, states, responsive behavior, accessibility, performance, and polish.

## Read only when needed

- Read [creative-direction.md](references/creative-direction.md) when candidate directions are converging too early or lack a distinct design thesis.
- Read [design-critic.md](references/design-critic.md) when reviewing a built interface, screenshot, or prototype and prioritizing revisions.
- Read [anti-ai-tells.md](references/anti-ai-tells.md) when the result feels generic, template-driven, overdecorated, or recognizably AI-generated.

## Completion signals

- The direction is clear and recognizable.
- Content and interaction are easy to understand.
- Key states have been validated.
- No high-priority usability issue remains.
- Further iteration no longer produces high-impact improvements.

## Guardrails

- Do not impose a framework, model, or vendor; honor the project's existing choices and use only available, authorized tools.
- Do not trade usability for novelty.
- Call paid services only when already authorized; never write credentials into code, generated artifacts, or commit history.
- Use visual references only as quality and atmosphere baselines; do not copy them.
