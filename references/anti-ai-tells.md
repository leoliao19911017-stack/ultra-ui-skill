# Anti-AI Tells

Deletion is not a minimalist doctrine. Keep any element that materially improves comprehension, action, feedback, or identity; simplify only when the interface becomes clearer or more purposeful.

## Patterns grounded in the public article

The public portion of the source article supports the patterns below. Its body is paywalled after the Technique 7 heading, so this Skill does not present any later material as read evidence or as the author's words.

| Symptom | Diagnostic question | Corrective action |
| --- | --- | --- |
| Unnecessary glows or gradients | Does the effect explain hierarchy, state, depth, or brand character? | Remove it or constrain it to the specific state it clarifies. |
| Random text highlights | Does emphasis map to meaning and reading order? | Highlight only meaningful terms; otherwise restore coherent type hierarchy. |
| Redundant labels | Would the control, value, or section remain clear without this text? | Delete duplicate labels or merge them with the primary title or value. |
| Empty decorative space | Does the space establish rhythm or focus, or merely inflate the page? | Tighten the composition or give the area a real content role. |
| Needless containers | Does the boundary express grouping, interaction, or state? | Remove the shell and use spacing, alignment, or typography to group content. |
| Custom controls worse than native | Does the custom version improve the task without losing familiar behavior? | Prefer the native or platform-standard control; custom-build only with a tested benefit. |

These are diagnostics, not a blacklist. A glow, container, or custom control can stay when its purpose is deliberate and its execution is strong.

## Production heuristics added by this skill

The following are production heuristics derived for this Skill, not claims or quotations from the article.

| Symptom | Diagnostic question | Corrective action |
| --- | --- | --- |
| Repeated card grids | Do separate cards reflect distinct objects or actions, or just a layout habit? | Merge related content and create hierarchy through structure instead of more cards. |
| Excessive pills | Does each capsule communicate a selectable state, compact status, or token? | Return ordinary labels and actions to text, links, or standard controls. |
| Uniform rounded rectangles | Are unrelated elements receiving the same shape and visual weight? | Reserve shape for semantics; vary grouping, edges, and emphasis intentionally. |
| Default hero-left / visual-right layout | Does this composition serve the content and desired first action? | Recompose around the product's strongest content, proof, or interaction. |
| Ornamental charts or fake metrics | Can the data be sourced, interpreted, and acted on? | Replace fabricated signals with real evidence, meaningful examples, or nothing. |
| Overlong copy | Is the text answering a user question or compensating for weak hierarchy? | Edit to the decision-relevant message and reveal detail where needed. |
| Weak empty, loading, or error states | Do non-happy states explain what happened and what to do next? | Design state-specific feedback, recovery actions, and accessible status messaging. |
| Motion without interaction value | Does motion confirm input, explain change, preserve context, or express identity? | Remove it, shorten it, or connect it to a meaningful state transition. |

Intentional, well-executed exceptions are valid. Judge the result against the product goal and constraints, not stylistic purity.

## Subtraction pass

For every visible element, ask: **Would removing it harm comprehension, action, feedback, or identity?** If not, delete or merge it. Then re-check hierarchy, spacing, typography, and color consistency; subtraction is incomplete if the remaining system still feels accidental.

## Production acceptance

Verify the interface with real content and long text; empty, error, and loading states; keyboard navigation and visible focus; sufficient contrast; reduced-motion preferences; mobile layouts; performance constraints; and native or platform conventions. Preserve the user's explicit preferences unless they create a concrete usability, accessibility, or delivery conflict.

Add imagery, video, 3D, or shaders only when they strengthen meaning or interaction. Inspect animation frame by frame, including loop seams, loading behavior, responsive crops or scaling, performance, and a usable fallback.
